# 09 · 闭环验收标准

> V0.2 拟议产品设计基线（2026-11-24）。源自 PRD V0.1 和 V0.2 闭环复评；非已实现功能或已通过工程验收。遇到 V0.1 原型与 V0.2 约束冲突，以 V0.2 为拟议修订基线。原型闭环覆盖复评见[学习闭环复评](../evaluation/learning-loop-review-v0.2.md)（本文仅保留唯一权威的验收标准与发布门禁，避免重复维护）。

## 12. 验收标准与发布门禁

### 12.1 P0 最小端到端验收集

> 首期模型验收以 **DeepSeek Flash** 为准；按阶段推进，M2-A 先验收 AC-01–04、AC-06 的主流程闭环，M2-B 补齐事务/CAS/幂等/崩溃恢复后验收 AC-05、AC-07，M3 在真机完成 AC-08 全量发布验收。

| 用例 | 给定 / 操作 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 LF01 | 配置外部模型（首期 DeepSeek Flash）；新建问答，追问并退出重启 | 原消息、模型及会话恢复；无额外服务依赖 |
| AC-02 Little Tutor | 选择消息片段并追问；关闭再打开 | 来源与子会话正确，主会话保持不变 |
| AC-03 Handoff | 从 LF01 创建目标；修改并确认大纲 | 来源保留、Path ID 稳定、Study 才开放 |
| AC-04 Mastery Gate | 独立答对三次，分别观察门槛；再测试错答/定性评估 | 分数按政策更新；无证据不达标；不强制所有类型同一流程 |
| AC-05 修复与恢复 | 题卡/作答/评分三个时点杀进程；重复提交/作废题目（M2-B 加固后全量通过） | 不重复计分、正确重算、恢复原题或评分 |
| AC-06 Review | 推进测试时钟使任务到期；正确、错误、使用提示各测一次 | 独立性标记正确；任务及下次日期更新；补救分支可进入 |
| AC-07 一致性 | 检查首页、列表、详情、工作台；修改大纲；导出/恢复（M2-B 加固后全量通过） | 相同 Revision 下数据一致，证据关联不丢失，备份可恢复 |
| AC-08 原生端 | Android ARM64 真机安装，无 Python 后端，完整执行 AC-01–07 | 可独立执行和重启恢复；更多模型扩展与 iOS 按后续计划验收 |

### 12.2 发布门禁

原型主路径和关键分支已覆盖，不代表功能已实现。M3 发布前，AC-01–07 与 AC-08 必须真实通过；M2-B 加固阶段的原子事务、故障注入、时间控制、证据有效性、评分复核、Revision 冲突及跨数据库恢复必须验收。P0 不扩大至多模型兼容矩阵、独立课程市场、内建 RAG、游戏或本地模型推理。
