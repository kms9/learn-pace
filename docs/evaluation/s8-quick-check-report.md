## 方法与调整

- 每组使用独立的模拟对话，依次发请求。TCP 与 UDP、数据库事务原子性两组带有助手回复选段。运行时最多发送最近 6 条消息，每条 800 个 Unicode 码点，选段最多 600 个码点。
- 请求关闭推理并将采样温度设为 0，使用 `response_format: json_object`。耗时从调用生成函数起算，包含模型返回、JSON 解析、校验与选项打乱。P50 和 P90 用最近秩计算。
- 初轮有 8 组结构合法，6 组通过完整展示检查。定向复测发现简答偶尔遗漏必填答案，个别题干或同一批中的另一道题会给出作答线索。另一次结构均通过的试跑中，人工发现了二分查找最大比较次数的边界错误。
- 最终提示词明确必填字段、计算校对和双题独立性。运行时复用题卡校验，并检查题干、其他题目的选项与导语，避免直接重复答案、可接受答案或解析。两题互相提示时保留能独立展示的一题。导语提前给出任何候选题的私有答案时拒绝本次生成。

## 复现

在仓库根目录执行以下命令。脚本读取本地 `.env`，输出每组计时和统计。逐题复核材料保存在忽略的 `tmp/s8-quick-check/` 运行目录，文件写入前会脱敏。

```sh
corepack pnpm --filter @learn-pace/runtime exec node --import tsx ../../scripts/s8-quick-check/run-verify.ts
corepack pnpm --filter @learn-pace/runtime typecheck
corepack pnpm test
```
