# Learn Pace · DeepTutor 手机版复刻方案（V0.3 草案）

2026-11-25 · 依据：DeepTutor `1284116` 源码、[学习流程源码对照（V0.2）](deeptutor-learn-pace-source-comparison-v0.2.md)、当前 M2-A Change 2–6 · 状态：第 2.3 节决策已确认；PRD、路线图与 OpenSpec 变更（Change 2、3′–6′）均已按本方案更新。与下文第 5.1 节的差异：Tab 改名、默认页与移除 P00 放在 Change 2（首个有真实界面的 Change），交接卡放在 Change 6′，`interactions` 的 `abandoned` 状态迁移放在 Change 3′（重置进度需要）

## 1. 结论

**目标**：打开应用，问答和精通之路两条流程的交互结构、导师行为、术语和视觉都让人认出这是 DeepTutor 的手机版。

**当前差距**：问答（LF01）已经接近 DeepTutor，需要中等调整。精通之路（LF02）差别在根上：

| | DeepTutor | 当前 Learn Pace 规格（Change 3–6） |
| --- | --- | --- |
| 谁推进学习 | 导师在对话里调用工具推进：建大纲、出题、批改、切换模式、延期；引擎守门 | Host 按页面和按钮推进：表单 → 生成按钮 → 确认按钮 → Study/Review 工作台 |
| 学习发生在哪里 | 一个「精通会话」：聊天流 + 题卡 + 顶部模式切换（编辑大纲 / 学习 / 复习） | P06 工作台按模式切换不同界面，复习有专用队列与结算页 |
| 大纲怎么定 | 导师在对话中提出、修改，学习者口头同意后导师切到学习模式；大纲随时可在「编辑大纲」模式修订 | 一次性 JSON 生成预览，点「确认」后只读 |
| 复习怎么做 | 路径页的复习计划列出到期项，点开就是一个复习模式的会话 | 专用复习队列、答题卡、结算卡片 |

**判断**：要达成目标，LF02 需要从「页面工作台」改成「导师驱动的精通会话」。这意味着 Change 3–6 需要重写，Change 2 需要中等修改。已经对齐上游的领域层（掌握度、间隔调度、评分管线、选点策略）可以保留，重写主要发生在 Runtime 工具层、Host 会话层和界面。

**最大风险**：DeepTutor 的导师循环依赖模型稳定地调用十余个工具。首期只有 DeepSeek Flash，M1 只验证过单个出题工具。建议先做一次技术验证（见第 6 节 S7），通过后再重写 Change 3–6。

## 2. 复刻边界

### 2.1 要复刻的

- 信息架构：学习首页、精通之路列表、路径页、精通会话、聊天、小老师侧聊的层级与跳转。
- 会话模型：一条路径可以有多个会话，会话有可切换的模式。
- 导师循环：工具名、模式权限、每轮状态快照、「出题即收尾」、作答在下一轮先由引擎批改。
- 题卡交互：选择题（可「用自己的话回答」）、简答/开放题、题组、跳过、复核判定、未定评分的澄清。
- 复习方式、路径页结构、升级庆祝、空会话的起手提示。
- 中文文案（`web/locales/zh/app.json`）与视觉风格（米白底、陶土色主色）。

### 2.2 保留 Learn Pace 差异的（工程约束，不影响「像不像」）

| Pi Durable 代替 DeepTutor 的 agent loop | D2/D4 已冻结；工具语义按 DeepTutor 移植 |

## 3. 流程逐项对照与调整

每项按「DeepTutor 怎么做 → 现规格 → 调整」写。上游路径均相对 `upstream/deeptutor/`。

### 3.1 应用壳与学习首页

- **DeepTutor**：工作区根路由直接跳转 `/chat`（`web/app/(workspace)/page.tsx`）。学习首页 `LearningDashboard` 有两块：「需要你关注」列出有到期复习的路径，一键进入复习会话；「学习记录」列出所有路径和进度。没有路径时展示学习方式入口卡片（`web/features/ui-layout/modern/LearningDashboard.tsx`）。
- **现规格**：Change 6 首页有三张统计卡（待复习 / 学习中 / 已掌握）、今日任务、场景筛选和题卡恢复卡。
- **调整**：
  - 首页改成 DeepTutor 学习首页（网页称「学习记录」与「该做的事」）：「该做的事」（到期复习、有待答题的会话）+「学习记录」+ 空态入口。统计卡、今日任务和场景筛选删掉。
  - Tab 按决定 A 命名，默认打开「问答」；P00 学习场景随决定 F 移除。
  - 视觉换成 DeepTutor 主题：浅色 `#fdfcf9` 底、主色 `#b0501e`，深色 `#1a1918` / `#d4734b`；卡片圆角 16–20；中英混排字体回退到系统中文字体（`web/app/globals.css`）。

### 3.2 自由问答

- **DeepTutor**：「新对话」、最近会话列表（排除侧聊和学习会话）、模型选择、停止生成、最后一条回复可「重新生成」、失败可「重试」、整轮可删除；消息用 Markdown + KaTeX 渲染（`web/features/chat/components/ChatWorkspace.tsx`、`ChatMessageList.tsx`）。能力选择器里有聊天、解题、主动提问、出题等多种能力，精通之路不在其中。
- **现规格**：Change 2 覆盖多轮、停止、中断恢复、重试、模型记录、渲染组件。
- **调整**：
  - 补「重新生成最后一条」和「删除整轮」。
  - 会话列表改为顶部按钮打开的底部弹层（对应网页的会话菜单）。
  - 不做能力选择器；保持单一聊天能力。LF01-05「理解验证」以后若做，对应 DeepTutor 的「主动提问」卡片，且明确不计入掌握度（`deeptutor/capabilities/ask_questions/capability.py`）。
  - 消息编辑与分支切换列为后续项。

### 3.3 小老师（Dito 侧聊）

- **DeepTutor**：选中文字后浮出工具条：「添加到对话框」「问 Dito」。侧聊打开后，Dito 能读到父会话到当前末尾的对话（每条最多 6,000 字、总计 24,000 字），新侧聊不自动发送，选文预填在输入框。原消息下显示「小老师 ×N」，可打开、删除或解除关联。侧聊不会把内容写回父会话；把内容带回主会话的方式是「添加到对话框」，选文作为引用附在下一条消息上（`web/lib/side-chat.ts`、`deeptutor/services/session/_turn_runtime_shared.py` 第 1180–1256 行、`web/features/chat/components/MessageThreadMarker.tsx`）。
- **现规格**：Change 2 只给子会话带入选文和来源提问；有「引用摘要回主会话」。
- **调整**：
  - 父上下文改为「父会话到最新一条的有界记录」，上限照搬 6,000 / 24,000。
  - 删除「引用摘要回主会话」，改为选文工具条上的「添加到对话框」：选文成为主会话输入框里的引用条。
  - 选文工具条的两个动作沿用 DeepTutor 文案「添加到对话框」「问 Dito」；消息下标记「小老师 ×N」，支持打开、删除、解除关联。
  - 手机端保留「长按消息 → 选文确认层」的方式，选区仍按消息原文计算。网页支持跨消息选区，手机端先只支持单条消息。

### 3.4 从问答进入精通之路

- **DeepTutor**：聊天里的导师可以调用只读导航工具 `mastery_topics`、`mastery_sessions`，再用 `mastery_open_session` / `mastery_new_session` 在回复里放一张交接卡：显示路径、进度、可编辑的「开场说」，按钮为「回到这次会话」或「开始学习」。工具本身不写学习数据，也不自动跳转（`deeptutor/tools/mastery_nav.py`、`web/components/chat/home/MasteryHandoffCard.tsx`）。从聊天新建路径，则是在新建向导的资料步骤里选这段聊天。
- **现规格**：消息上的「转为学习目标」带四个参数跳到 P04。
- **调整**：
  - 聊天工具白名单加入这四个只读导航工具，回复中渲染交接卡。
  - 「转为学习目标」保留为消息操作，但改为打开新建向导，并把这段聊天和选文预选为资料。

### 3.5 新建精通目标

- **DeepTutor**：两步弹窗。第一步写目标（必填，最多 2,000 字）并选一个表情图标；第二步选资料（可不选）和模型，按钮「和导师一起设计大纲」。提交后创建一条空路径，立刻进入「编辑大纲」模式的新会话，并自动发送开场消息「用我选的资料，和我一起制定……」（`web/components/space/learning/CreateTopicWizard.tsx`、`web/lib/mastery-mode.ts`）。
- **现规格**：Change 3 的 P04 收集目标、路径名称、背景与目标程度；然后到 P06 点「生成大纲」。
- **调整**：
  - 按 DeepTutor 两步重做：目标 + 图标 → 资料（问答会话、选文、文本笔记）+ 模型。
  - 背景、目标程度改由导师在大纲对话里了解，并通过 `mastery_profile` 保存。
  - 路径名称由导师在建大纲时给出，之后可在路径页改名。
  - 提交后直接进入大纲会话并自动发出开场消息。

### 3.6 编辑大纲模式

- **DeepTutor**：导师先了解学习者，再用 `mastery_build` 建出大纲（路径一有知识点就可学习）。之后的修改用 `mastery_revise`：小改直接改，大改先预览再提交。预览带基线版本，过期即拒绝；知识点按「名称 + 类型」保持稳定 ID。学习者在对话里同意后，导师调用 `mastery_mode` 切到学习模式。界面上，大纲侧栏实时刷新；当大纲已有内容时，会话顶部出现「大纲已就绪——共 N 个知识点」横幅与「开始学习」链接。路径页另有「编辑模块」手工编辑器。没有「确认大纲」按钮，也没有可视化的差异对比（`deeptutor/capabilities/mastery/tools.py` 的 `mastery_build` / `mastery_revise`、`deeptutor/learning/outline_revision.py`、`deeptutor/learning/service.py` 第 240–306 行与第 1945 行起、`web/components/space/learning/MasteryStudy.tsx` 第 807–833 行）。
- **现规格**：Change 3 一次性生成 JSON 预览，落库为 `outline_draft`，点确认后路径从草稿变进行中，大纲只读。
- **调整**：
  - 删除 `outline_draft`、确认按钮和草稿状态，改为导师工具 `mastery_build`、`mastery_revise`（含预览/提交与版本校验）。
  - 移植上游的语义身份规则和 `outline_revision`。
  - 会话内大纲用可折叠的底部弹层展示（替代网页的右侧栏），并加上「大纲已就绪」横幅。
  - 先修关系的 DAG 校验保留，上游同样有。
  - 「编辑模块」手工编辑器列为后续项。

### 3.7 精通会话与学习模式

- **DeepTutor**：
  - **会话**：一条路径可开多个会话，路径页可恢复任何一个；会话顶部有「编辑大纲 / 学习 / 复习」切换，用户可切换，导师也可用 `mastery_mode` 切换。
  - **导师循环**：每轮都能拿到状态快照（下一个目标、待答题、到期复习、整份大纲、学习者画像）。一轮要么只说话，要么以 `mastery_quiz` 出题收尾；以冒号结尾就必须出题。
  - **工具**：讲解后用 `mastery_note_explained` 记录教过什么；学习者卡住时可用 `mastery_defer_objective` 延期，或用 `mastery_repair_question` 报告题目有误。
  - **选点**：下一步用官方 `next_objective`，顺序为：待答题 → 到期复习 → 按模块顺序的第一个未掌握目标；有效动作是 probe / teach / practice / assess / complete。
  - **空会话**：显示「接下来」和三个起手提示（`deeptutor/capabilities/mastery/mode.py`、`loop.py`、`pipeline.py`、`prompts/zh/mastery_loop.yaml`）。
- **现规格**：Change 4 由 Host 区分「讲解回合」和「出题回合」，每条路径一个 Study 会话；用 `selectStudyObjective` 选点，界面有提示、延期按钮。
- **调整**：
  - Runtime 层实现精通工具集与模式权限（工具一律挂载，执行时按模式校验，与上游相同）。
  - 每轮注入 `mastery_status` 快照，并把中文导师提示词按 Apache-2.0 移植（保留出处）。
  - 会话改为「每路径多个、模式可切」，`sessions.mode` 可变。
  - 选点改用已移植的官方 `nextObjective`（冲突 B）。
  - 延期、报错题改由导师工具完成；题卡上只保留「跳过」和「复核判定」。
  - 空会话展示「接下来」和三个起手提示。
  - 学习者画像在路径页显示，由导师维护（`mastery_profile`）。

### 3.8 题卡与评分

- **DeepTutor**：
  - **出题与展示**：`mastery_quiz` 出题后本轮结束。选择题选项打乱展示，答案按标签保存。题卡支持「用自己的话回答」和 2–4 小题的题组。
  - **作答与批改**：作答作为下一条消息提交。引擎先保存答案，在导师开口前批改：选择题和可接受答案精确比对，其他用语义判定；结果为「未评分」或置信度低于 0.8 时不定分，由导师澄清。
  - **定性题**：`mastery_assess` 取学习者这一轮的原话评估，忽略模型给出的 `passed`。
  - **题卡按钮**：「跳过」和「复核或申诉本次判定」。
  - **掌握反馈**：知识点首次掌握时播放升级庆祝动画（`deeptutor/learning/question_card.py`、`semantic_assessment.py`、`deeptutor/services/session/turns/learning_adapter.py`、`web/components/chat/home/MasteryQuestionCard.tsx`、`LevelUpCelebration.tsx`）。
- **现规格**：Change 4 定量只出选择题、定性只出开放题；有提示按钮；评分管线已按上游移植。
- **调整**：
  - 保留已对齐上游的评分管线。
  - 新增「作答即下一轮、导师开口前先批改」的时序，以及 `mastery_grade` 工具（用于学习者在输入框里直接作答的情况）。
  - 移植语义判定（用 DeepSeek Flash 输出 JSON），支持简答题、题组和「未评分、待澄清」。
  - 题卡加「用自己的话回答」「跳过」「复核判定」。
  - 删除提示按钮（冲突 E）。
  - 加升级庆祝动画。

### 3.9 复习模式与复习计划

- **DeepTutor**：
  - **复习方式**：复习就是复习模式的会话，只允许对已掌握知识点出题（`_review_scope_refusal`），评分规则与学习相同。
  - **入口**：学习首页的到期卡片、路径页的「接下来」、复习计划里每一项的播放按钮，进入时自动带上列出到期项的开场消息。
  - **复习计划面板**（路径页）：
    - 列出到期与即将到期项、遗忘风险和原因；
    - 提供复习策略选择、自定义间隔，以及 70%–99% 的回忆目标。
  - **结算**：没有单独的结算页（`web/components/space/learning/ReviewTrail.tsx`）。
- **现规格**：Change 5 有专用复习队列、提示、答后讲解回合、结算卡片和开发时钟。
- **调整**：
  - 改为复习模式会话 + 路径页复习计划面板。
  - 复习失败后掌握回落、回到学习的规则已与上游一致，保留。
  - 删除结算卡片（冲突 D）。
  - 复习策略选择和回忆目标调整：领域层已有 `review-strategy.ts`，自定义间隔编辑器列为后续项。
  - 开发时钟保留，用于真机验证。

### 3.10 路径页

- **DeepTutor**：

## 4. 技术架构调整

### 4.1 精通能力（Runtime + Host）

| 工具 | 模式 | 说明 |
| --- | --- | --- |
| `mastery_status` | 全部 | 状态快照；每轮由 Host 预先注入 |
| `mastery_profile` | 全部 | 保存学习者画像与教学偏好 |
| `mastery_mode` | 全部 | 切换模式；学习模式要求大纲非空 |
| `read_source` | 全部 | 读取本路径的本地文本资料 |
| `mastery_build` | 编辑大纲 | 新建或替换大纲（语义身份） |
| `mastery_revise` | 编辑大纲 | 修改大纲：直接修改，或预览后提交（版本校验） |
| `mastery_quiz` | 学习、复习 | 出题并结束本轮（现有 `register_question` 改名扩展：题组、简答、打乱选项） |
| `mastery_grade` | 学习、复习 | 批改当前待答题 |
| `mastery_assess` | 学习、复习 | 定性评估，取学习者原话 |
| `mastery_note_explained` | 学习、复习 | 记录讲解覆盖 |
| `mastery_defer_objective` | 学习、复习 | 延期知识点 |
| `mastery_skip_question` | 学习、复习 | 放弃当前题 |
| `mastery_repair_question` | 学习、复习 | 作废或更正有误的题 |
| `mastery_topics`、`mastery_sessions`、`mastery_open_session`、`mastery_new_session` | 问答 | 只读导航与交接卡 |

- **工具挂载与权限**：工具一律挂载，执行时按会话模式校验并返回拒绝原因（与上游 `ensure_mode` 相同）。
- **路径绑定**：路径和会话 ID 由 Host 绑定，模型不能任意指定，符合 PRD 06。
- **并发**：同一路径同时只允许一个运行中的导师回合，在内存中加锁，相当于上游的路径租约。
- **提示词**：移植 `prompts/zh/mastery_loop.yaml`，删去知识库、PDF、视觉题等本期不支持的段落。在 `NOTICE` 中注明来源，以及 DeepTutor 的 Apache-2.0 许可证。
- **作答时序**：题卡提交 → 保存答案 → 引擎批改 → 把批改结果作为本轮上下文 → 导师回复。

### 4.2 数据

- `sessions` 表已有 `path_id` 与 `mode`：一条路径对应多个会话，模式可更新；会话偏好（侧聊锚点等）放在会话元数据里。
- 待答题仍以 `interactions` 表为准，在状态快照里以 `pending_interaction` 的形式提供，同时满足 `nextObjective` 的 `answer_pending` 语义。
- 大纲预览需要存放预览号、基线版本、摘要和过期时间，可用内存或新表，1 小时过期，与上游一致。
- 领域层可直接复用：`computeMastery`、调度器、`nextObjective` / `mapSummary` / `objectiveReport`、DAG 校验，以及已按上游修订的评分管线。
- 需要新增移植：语义判定、大纲语义身份与修订规划、题卡打乱与题组、`next-step-copy` 文案表。

### 4.3 从现规格中删除

`selectStudyObjective` 的强制先修拦截、`outline_draft`、草稿确认按钮、Host 编排的「讲解回合 / 出题回合」、题卡提示按钮与追问自动记辅助、复习队列页与结算卡、首页统计卡与今日任务、P04 的背景/目标程度/路径名字段、「引用摘要回主会话」。

## 7. 风险

- **模型能力**：DeepSeek Flash 的长提示词与多工具调用稳定性未经验证；状态快照加提示词每轮可能超过 1 万 token，影响首字延迟和费用。由 S7 先行验证。
- **可测性下降**：导师驱动的流程不再由按钮决定，单元测试需要用脚本化的模拟工具调用覆盖；真机验收以场景走查为主。
- **规格重写成本**：Change 3–6 重写后需要重新评审；已在评审中对齐上游的评分规则与复习回落规则可以直接沿用。
- **原型过时**：V0.2 原型（D03–D07）与新交互不一致，评审时以本方案与上游源码为准。
