# Design

## Context

现有 Skill 服务已经校验下载字节、生成目录摘要并在确认后写入修订。SQLite 的来源约束限于本地和 GitHub。市场使用 Phase 14a 已验证的 Expo 流式网络传输。

## Goals / Non-Goals

公开目录与安装入口共用技能库的预览、启用、绑定和更新。市场网络只在用户浏览、预览或主动更新时使用。

## Decisions

1. 默认 EduHub，另设腾讯 SkillHub 和 ClawHub。EduHub 与 ClawHub 使用各自公开的列表、搜索、详情和版本验证接口。SkillHub 使用公开列表、详情和文件摘要接口，验证受控对象存储跳转。
2. Host 在确认前核对发布者和精确版本，校验来源声明的文件字节与 SHA-256。ClawHub 的 GitHub 来源沿固定公开提交获取并以相同清单核对。ZIP 的市场生成元数据仅在清单声明时进入技能资源。
3. 市场技能沿用 `skills` 表，增加 `registry` 来源类型。来源标识使用市场与发布者及 slug，版本保存在现有 `pinned_ref`，原始包字节仍以独立目录摘要固定。v9 原子迁移保留已有行；备份 v2 在 schema 9 使用同一套 13 表并恢复 schema 8/7 与历史 v1。
4. 对 OpenClaw 的嵌套元数据做受限解析，保留原始包字节并标出未满足的平台需求。市场声明的依赖只用来判断是否可用，工具能力由现有 Host 目录控制。

## Risks / Trade-offs

- 各市场的列表及下载响应会演进，需用公开真实样本与本地契约测试分别验证。源站限流或校验失败时保留现有技能数据与可重试入口。
- ZIP、验证响应与传输时限均受上限约束。市场正常状态下允许运行的技能仍由用户显式启用，第三方描述和正文仅作为不可信内容展示或注入既有 Skill 边界。
