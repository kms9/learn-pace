# Design

## Context

参见 `proposal.md`、`docs/evaluation/deeptutor-mobile-parity-plan-v0.3.md` §3.9 与 `docs/prd/04-lf02-mastery-flow.md` §6.3、§7.3。本 Change 建立在 Change 3′ 的精通会话与 Change 4′ 的题卡和评分管线之上；评分管线已从首次评分起维护复习状态，复习计划只显示已掌握的知识点。

DeepTutor 参照（`upstream/deeptutor`）：
- 复习模式：`deeptutor/capabilities/mastery/mode.py`（复习不以到期为前提）、`tools.py` 第 586–616 行（`_review_scope_refusal`）、`prompts/zh/mastery_loop.yaml` 的 `session.review`。
- 入口与开场：`web/lib/mastery-mode.ts`（`masteryOpeningMessage("review", { dueTitles })`）、`TopicAtlas.tsx` 第 67–106 行、路径页第 371–379 行与第 570–578 行。
- 复习计划：`web/components/space/learning/ReviewTrail.tsx`；领域 `review_strategy.py`、`scheduler.py`。
- 文案：`web/locales/zh/app.json`（「复习计划」「按遗忘曲线安排」「复习策略」「默认」「记忆保持目标」「现在可复习」「开始本次复习」等）。

## Goals / Non-Goals

**Goals:**
- 复习的入口、会话行为与复习计划面板与 DeepTutor 一致。
- 复习失败、补救与再入队的状态变化可测、可在真机复现。

**Non-Goals:**
- 结算页、提示按钮、自定义间隔编辑器、故障注入套件、事务与 CAS。

## Decisions

### 1. 复习模式规则
- 复习模式下 `mastery_quiz` 与 `mastery_assess` 只接受当前已掌握（含自报）的知识点，否则返回「复习只考已经掌握的知识点」拒绝原因；其他学习工具照常按模式校验。
- 状态快照增加 `reviews`：到期项（按遗忘风险、逾期时长、优先级排序，与 `dueReviews` 相同）与 7 天内即将到期项，各含知识点、到期时间、遗忘风险、原因、失误次数。`next` 仍按官方 `nextObjective`，到期复习优先。
- 复习模式提示词使用 DeepTutor `session.review` 原文，并在末尾补一句：「复习告一段落或学习者想结束时，在会话中总结本次复习了哪些知识点、各自结果与下次复习时间；没做完的到期项保留到下次。」这是 Learn Pace 为替代结算页做的补充，在 `NOTICE` 与提示词文件中标注。

### 2. 复习失败、回落与补救（沿用 Change 4′ 的评分管线）
- 复习作答经 `applyGrade` / `recordQualitativeAssessment` 写入，与学习相同。
- 定量知识点独立答错：`quality = 0` 进入调度器失误分支，`lapse_count` 加 1、稳定度下降、间隔缩短；同时作答记录使掌握度跌破 0.9（三对一错约 71.4%，五对一错 75%），知识点回到学习中，离开复习计划；路径若为已完成则回到学习中。
- 定性知识点独立判为 `partial`：撤回定性掌握；其质量 0.5 恰等于失误阈值，调度器不计为失误，`lapse_count` 不增加。判为 `incorrect` 按失误分支处理。
- 辅助作答保持原掌握结论，证据质量封顶 0.6，复习状态仍随本次结果更新。
- 补救：回落的知识点由 `nextObjective` 在学习模式中自然选中；导师会在复习会话中建议切到学习模式或新开学习会话。重新达标即补救完成（定量知识点需让失误移出最近 5 次有效独立作答窗口，即连续 5 次独立答对）。补救作答沿用同一复习状态；重新达标后知识点按当前 `next_review_at` 回到复习计划并保留失误次数；若补救都在同一调度窗口内，连续答对沿用失误后缩短的到期时间。
- 同会话防刷：调度器在同会话窗口（最长 0.25 天）内对重复答对只增加复习次数，不推后到期时间。

### 3. 复习入口与开场消息
- 「精通之路」列表：存在到期项时顶部显示「N 项待复习」横幅，点击进入第一个有到期项的路径，新建复习模式会话。
- 路径页「下一个」动作为 `review` 时显示「复习这个记忆信标」与「开始本次复习」，新建复习会话。
- 复习计划每一项的开始按钮新建复习会话，开场消息只列出该项。
- 开场消息：有到期项时发送「我们来复习今天到期的这几项：{名称以「、」连接}。」，否则发送「我们来复习一下我已经学过的内容。」（DeepTutor 原文）。会话内手动切到复习模式不发送开场消息。

### 4. 复习计划面板（路径页）
- 标题「复习计划」，说明「按遗忘曲线安排」；右侧显示到期数量。
- 列表：已掌握知识点的复习项，到期显示「现在可复习」，未到期显示相对时间（如「3 天后」）；遗忘风险百分比、原因（调度器 `reviewReason`）、近期失误标记；点某项在大纲中定位该知识点，开始按钮进入复习。
- 「复习策略」：「默认」与四个内置模板（`builtinReviewTemplates`：日常长期学习、考前冲刺、语言类、理科类；中文名称为 Learn Pace 翻译），选择后绑定到路径并按新间隔重排。
- 「记忆保持目标」：70%–99% 滑杆，松手后调用 `setDesiredRetention` 重排复习计划并保存。
- 空态：「今天没有待复习的内容。继续学习，到时间会自动提醒你复习。」（DeepTutor 原文）。

### 5. 开发用时钟
- `AppContext` 向精通会话、路径页、列表（以及 Change 6′ 学习首页）提供同一个 `Clock`。Release 为系统时钟；`__DEV__` 构建在「我的」的开发区提供「时钟偏移（天）」，只保存在内存，重启归零。真机验证到期复习依赖它，因为按上游调度，知识点达标后的首次复习通常在数小时到数天之后。

## Risks / Trade-offs

- **[Risk] 没有结算页，学习者可能不清楚本次复习的结果** → Mitigation：提示词要求导师总结；题卡上保留每题结果；路径页复习计划随即更新。
- **[Risk] 一次失误即回到学习中，且需要连续 5 次独立答对才能重新达标** → Mitigation：这是上游既定规则，M2-A 不调整；导师与证据抽屉说明原因与当前得分。
- **[Risk] 开发时钟误入正式构建** → Mitigation：入口与数值以 `__DEV__` 守卫，不写入设置表；Release 构建检查入口不存在。
