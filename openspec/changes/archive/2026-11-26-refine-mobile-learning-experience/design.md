## Context

见 `proposal.md` 的复盘清单。当前问答有原文确认层、严格的来源区间校验和侧聊持久化。精通会话以会话投影展示题卡，学习和复习共用路径摘要与进度。移动端现有未提交版面调整包含共用输入栏和向导固定操作区。

## Goals / Non-Goals

- 让作答焦点、原文引用、会话去向和下一步学习任务可以直接操作。
- 修改集中在应用界面和应用 Host，沿用现有的存储和领域规则。

## Decisions

1. 复用原生 Markdown 组件的选区。Android 由 Markdown 组件上报选区，应用在输入区上方显示操作，兼容系统菜单只显示标准动作的设备。iOS 通过系统选区菜单提供操作。应用 Host 只接受原始消息的连续区间。唯一可确认的字面匹配或常见内联格式投影可直接提交。重复文本、公式占位无法对齐等情况走既有原文确认层，提供选文预览和可选择的原文位置。侧聊使用已保存的原文作独立引用，单条进详情，多条进列表，管理入口保留在会话菜单。
2. 文本答案聚焦时，由题卡把下一题与提交动作发布给会话底栏。题卡继续持有答题草稿，聊天草稿仍由会话持有。键盘关闭和焦点退出后恢复聊天输入。使用现有提交和批改方法。
3. 精通列表为每条到期路径提供明确按钮。路径详情上移进度、下一步和大纲，档案置于次级位置，路径操作归入「更多」。会话副标题使用同一投影的当前知识点。
4. 历史弹层和向导在本地会话标题上搜索。历史弹层随键盘上移，结果可直接点选。向导默认显示有限数量的最近会话，可展开。问答会话顶部使用已保存的标题，首轮标题随流式会话记录更新。起手示例只填充空草稿。
5. 交接按钮放在开场预览前。折叠预览保留保存的开场说，展开后可以编辑。问答和导航工具提示都要求短说明并省略内部 ID。

## Risks / Trade-offs

- 原生选区以渲染块为单位，区间与原始 Markdown 不总是一致。只有可验证的唯一原文匹配直接执行，其他选区仍可精确确认。
- Android 返回键关闭输入法时文本框可能仍聚焦。监听键盘关闭并退出题卡输入工具栏，验证重新聚焦与草稿恢复。
- 真机验收使用已有的隔离测试包。验收记录区分实测和代码或单元测试覆盖的分支。
